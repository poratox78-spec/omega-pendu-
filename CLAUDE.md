## Ce dépôt contient 4 choses
1. **OMEGA-Ω** — moteur cognitif de **pendu français** (`app/omega-pendu.html`, monolithique). Doctrine **« cognition > oracle »** + **R66** (mesurer/falsifier avant de garder ; tout module OFF par défaut, baseline byte-identique). Détails : `docs/MEMOIRE.html` + `docs/rapport-mode-emploi.html`.
   - ⚠️ Le lexique embarqué est **compressé** : bloc `<script type="text/plain" id="lex4-data-gz">` (gzip+base64) ; `loadOmegaLex4()` est **async** et décompresse via `DecompressionStream` (navigateur ≥ 2023). Fichier ~5 Mo.

3. **`evo/`** — workstream exploratoire : *OMEGA apprend à coder* (se copie ; le pendu = test de fitness lexicographique win→erreurs→temps). Harnais headless : `evo/fitness_harness.js`. Plan : `evo/EVO_ROADMAP.md`.
4. **`dictee/`** — **SOUS-PROJET ACTIF** : *dictée diagnostique* (cible **dys / troubles de l'écrit**) sur la **double route** d'OMEGA.

## Chantier actif = dictée. ÉTAT ACTUEL : DICTÉE DE PHRASES
Cadre tranché (audit) : **dictée de phrases** (le contexte rend homophones ET accords gradables, **sans M3_d**). Intégrée dans `app/omega-pendu.html` en **panneau additif OFF-inerte** (IIFE, bouton « ✍️ Dictée diag »).
- `dictee/diag_sentence.py` — **moteur de diagnostic de référence** : aligne (Levenshtein) cible/élève, diagnostique chaque mot. Familles : **accent · voisée-sourde · inversion · muette · ajout · homophone · accord · surface · omission · mot-en-trop**. `is_accord` = diff flexionnelle vs homophone lexical ; `norm()` = normaliseur phonétique pour la **surface** (leson→leçon). **Mesuré (synthétique) : 100 %/famille, surface 17/17.**
- `dictee/sentences.json` — 30 phrases graduées (10/10/10) + `traps` (familles exerçables) + familles d'homophones par mot.
- `dictee/phono_homophones.json` — index homophones **PLEIN** (43 580 groupes, ~2,1 Mo, sans filtre freq).
- **Levier GRAMMAIRE** (dans `diag_sentence.py`) : accord **en contexte** — sujet-verbe (94 %), sujet à distance (`skip_pp`), participe passé (être / avoir+**COD antéposé**), **genre du GN** (`governor_gender` + **route lexicale** `lexical_gender`), désambiguïsation homographes nom/verbe. Stades développementaux (Ferreiro/Berliocchi) : phonologique→alphabétique→lexical→morphosyntaxique.
- **CORRECTEUR DYS** (`dictee/correcteur_probe.py` + panneau app « 🩹 Correcteur ») : détecte **et corrige** **sans corrigé** (1) les homophones grammaticaux (a/à, son/sont, on/ont, leur/leurs, -é/-er, peu/peux/peut, ce/se, et/est) ET (2) l'**accord SUJET-VERBE** — sujet **pronom** (« Je doit »→dois, « On ont »→a, « il sont »→est) **et sujet NOM** (déterminant pluriel en tête : « les enfants **joue** »→jouent, « Les oiseaux **chante** »→chantent) — via la table de conjugaison Lexique 4 `cgram_conj.json`. **0 faux positif** (30 phrases + témoins + **98 phrases réelles GEC** + held-out) ; held-out accord SV **11/11 sur vocabulaire neuf**. Sujet-nom borné FP=0 **sans lexique de noms** (déterminant pluriel en tête → pas de génitif/PP à gauche). UI semi-directe : clic = applique la correction + **stade**. **Parité app↔Python** en CI (`parity_corr.js`). Garde-fou anti-bruit Lexique : 1re/2e pers.=personne seule, infinitif écarté, nombre déduit de la morphologie, suggestion cross-validée. (3) **GENRE DÉTERMINANT** (un/une, le/la… via `cgram_gender` noms purs `gn` ; 17/27 sur GEC réel, FP=0, parité app) **+ garde POS-155k** (`build_pos.py` extrait `cgram_pos.json` du lexique EMBARQUÉ `OMEGA_LEX4` — §5 réutilise le gros lexique du pendu ; abstient si le mot après le déterminant a POS≠NOM ∨ nbhomog>1 → genre 91→61 FP sur UD French, parité 3 moteurs via asset `pos-abstain.txt.gz`). (3bis) **ACCORD PLURIEL DU NOM** (« des ami »→amis, « les enfant »→enfants — la faute dys n°1 ; `rule_noun_plural`/`rNounPlural` : dét. pluriel + nom singulier `POS==NOM ∧ nbhomog==0`, pluriel **ancré dans le lexique 155k** = oiseau→oiseaux/cheval→chevaux, jamais « oiseaus » ; gardes composé/unité/latin ; **22 FP UD dont ~18 vraies prises**, parité 3 moteurs via asset `nom-nbhomog.txt.gz`. Homographes verbe/adj « les porte/livre », « des ami »/« les faute » **abstenus** = FP-safe). (4) **COUCHE ORTHOGRAPHIQUE temps réel** (`dictee/speller_probe.py` + miroir JS app) : corrige les **non-mots** (accents/typos/phonétique) via le lexique complet — **AUTO** (remplace seul les accents sûrs : fenetre→fenêtre, **FP=0/98 GEC**) + **FLAG** (souligne : leson→leçon, gâteau, l'année). Bloc embarqué `speller-lex-gz` (92 743 formes, `build_speller_lex.py`). Vérifié headless en CI (`test_speller_app.js`). Détail : `dictee/CORRECTEUR.md`.
- **Lexique4 reçu** → `dictee/build_cgram.py` génère (dérivés CC BY-SA) : `cgram_verbs.json` (12 415 verbes), `cgram_gender.json` (53 050 noms genrés non ambigus), `cgram_adj.json` (16 755 paires de genre), **`cgram_conj.json`** (table de conjugaison 8 018 formes / 2 404 lemmes pour l'**accord sujet-verbe**), `cgram_hf.json` (sous-ensemble HF verbes+genre+**conjugaison présent/imparfait** **embarqué dans l'app**, bloc `<script id="vdc-lex">`). C'est la **route lexicale** de la grammaire à double voie.
- **Grammaire à double voie** (`dictee/GRAMMAIRE_DOUBLE_VOIE.md`) : route lexicale (cgram) × sublexicale (règles) + boucle montante (décider) × **descendante** (`descending_probe.py` : apprend le lexique de genre depuis l'usage, **100 % préc., FP=0, data-bound**).
- **DÉCOMPOSEUR « à la Lexique 4 »** (`dictee/decompose.py` + `dictee/DECOMPOSE.md`, panneau app « 🔤 Décompose ») : lit/apprend des mots, les décompose en **SON et ORTHO** (double voie). Route **sublexicale** = `g2p()` de l'app **extrait** en `g2p_tables.json` (`build_g2p_tables.py`) **+ SEG enrichi (8 segments mesurés) + correction apprise** (`build_g2p_corrections.py` → `g2p_corrections.json`, boucle descendante : alignement g↔p sur Lexique, 667 règles) **+ syllabation par règles** (attaque maximale, son+ortho). Route **lexicale** = `phono_homophones.json` (phono SAMPA + nbhomoph) + `cgram_*`. **Apprend** = `learned_lex.json` incrémental (**FP=0**, non versionné). Mesuré **held-out** (seed 42, test=4000, in-lexique⟂OOV) : sublexical **48,6 %→52,4 % exact / 89,5 % phonémique** (échelle SEG/correction). ⏳ panneau app = sublexical encore brut (parité à porter).
- **MORPHOLOGIE** (`dictee/build_morpho.py` → `morpho.json`, 20 523 mots) : décompo morpho « comme Lexique 4 » (champs `md/mb` décodés d'OMEGA_LEX4), route **lexicale** (`portable→port+able [/port(er).able]`) × repli **sublexical** par affixes (`antibrouillage→anti+brouill+age`). Couverture test : lexicale 14 % · sublexicale 54 %. **Croisé/validé** contre vérité Lexique (OMEGA_LEX4 décodé) : ma **nbsyll = 100 %** du gold, CV = convention `cvp`.
- **COGNITION Phono→Ortho** (`dictee/p2g.py` + `build_p2g.py` → `p2g_table.json` ; `dictee/P2G.md`) : **l'inverse** du décomposeur (son→écriture, *le* point dur dys). Jointe **§3** (pas argmax) : beam-search marginalisant la segmentation latente, **triple croisement** émission (route SON) × prior ortho bigramme (route ORTHO) × **lexicalité** (vrai mot). Mesuré held-out : **top-1 26,7 % · top-3 64 % · top-5 73 %** (lexicalité = gros levier ; plafond bridé par 2,3 homophones/mot ; fréquence testée et **rejetée**). Dette §A2 : le moteur a déjà `L2`/`_neoCRS`/`_neoDeclareOSmix` (réutiliser `L2` = jonction future). Compressibilité base : 7,9× gzip, **17× factorisé** (`compress_probe.py`). Régression gardée : `test_decompose.py` (asserts + seuils).
- Panneau app « 🔤 Décompose » : route lexicale lit aussi `md/mb` + voisins **`PLD20`** d'OMEGA_LEX4 (parité Lexique 4, mots ≥7 lettres). ⚠️ **`OLD20` câblé à vide** : `lexLookup` lit `e.old` défensivement mais la colonne **n'est PAS embarquée** (0/155 493) → toujours `null`, jamais affiché. Embarqué réel = **11 dims** : `m p g f prev pld md mb l nbhomoph nbhomog` (OLD20/syll/cvo/cvp **régénérables** depuis `Lexique4.tsv` en asset, pas gratuits).

## Décisions clés (ne pas re-débattre)
- **Cible n°1 = dys / troubles de l'écrit.** **Cadre = phrases** (mots isolés = mal posés : 84 % ont des homophones).
- Pourquoi dictée : **phon→ortho = force mesurée** d'OMEGA ; **profil de défaite = signature dyslexie phon** (rapport §11.2 : 58 % voisée/sourde).
- **Débouché applicatif = CORRECTEUR DYS** (détecte+corrige+situe le stade). Il roule sur le moteur de **dictée**, pas sur le pendu → toutes longueurs, régime mot-court (où l'accord paie). Garde-fou cardinal : **FP = 0 sur batterie** ; **mesuré 2,35 % sur français encyclopédique réel** (UD French, 16 342 phrases ; 6,0 %→2,35 % par 5 lots de durcissement + **POS-tagger 155k** réutilisant le lexique embarqué, tous FP-safe=abstention, `dictee/fp_stress_test.py`) — le domaine dys est plus bas, pas 0. Détail : `dictee/JOURNAL.md`.
- **FALSIFIÉ — NE PAS REFAIRE** : (a) M3_d ne désambiguïse pas les homophones (aucune entrée sens/contexte) — `dictee/README.md` (§ « Falsifié M3_d ») ; (b) **pendu de phrases** comme levier winrate : le partage de lettres fuit les fins → la valeur est dans la *déclaration*, mesurée marginale sur le moteur ≥7 — `evo/PHRASE_HANGMAN_PROBE.md`. *Nuance* : le **readout bPC** de M3_d (cLetterScore) est « peut-être utile » (+3,4, cheat-free) — `AUDIT_OMEGA.md` §3 ; (c) **C cognitif OOV** (`AUDIT_OMEGA §1.8-1.12`) : la cognition seule fait ~11 % OOV ; le levier est l'**agrégation** = n-gram (§1.7) branché en **voie sublexicale arbitrée OS** (§1.9, bascule auto par fiabilité, in-lex ~97 %/OOV ~60 %) + **gap-aware** (§1.10, plus proche voisin révélé à distance 1..4, **+2 pts OOV** = 1er gain cognitif réel). **FALSIFIÉS — ne pas refaire** : lissage par substrat `letterVecsSDIM`, pooling position-relative, le **C *léger* appris** (maxent/GATE/POE, `evo/learned_c_probe.js`), ET le **C *lourd* (transformer)** — construit + mesuré (§1.12, sonde `evo/heavy_c_probe.js` ; winrate à config optimale `evo/heavy_c_winrate.js`, hook moteur `_neoHeavyCDist` OFF-inerte) : **parité** avec le gap-aware (OOV Δ −1,3, perd 2/3 graines), l'entraînement sur **vraies parties** (`evo/harvest_states.js`) **recule** (−14,6, couverture lexicale). **Ne PAS câbler.** Au-delà = SOTA-scale hors-ligne → arbitrage explicite requis (c'est là qu'IndexedDB des poids deviendrait justifié).

## Comment lancer
- `python3 dictee/diag_sentence.py` → diagnostic de phrases + levier grammaire (autonome ; charge cgram si présent).
- `python3 dictee/correcteur_probe.py` · `eval_externe.py` · `descending_probe.py` → mesures correcteur / held-out / boucle descendante.
- `python3 dictee/build_cgram.py` → régénère cgram_* (attend `/tmp/lex4/Lexique4.tsv`).
- `python3 dictee/build_pos.py` → extrait `cgram_pos.json` (POS-tagger 155k) du lexique EMBARQUÉ de l'app (sans Lexique4) — garde genre du correcteur · `UDFR=/tmp/udfr python3 dictee/fp_stress_test.py` → mesure le taux de FP réel (UD French ; `FP_MAX=` = garde CI).
- `python3 dictee/build_g2p_tables.py` puis `build_g2p_corrections.py` (boucle descendante) → tables g2p + table de correction · `python3 dictee/decompose.py "mot" | --read "texte" | --lex | --measure | --demo` → décompose (son/ortho) + apprend. Sublexical mesuré **held-out 52,4 % exact / 89,5 % phonémique** (SEG enrichi + correction apprise + syllabation par règles).
- `python3 dictee/build_morpho.py` → morpho Lexique 4 (md/mb) · `python3 dictee/build_p2g.py` puis `python3 dictee/p2g.py "wazo" | --mot oiseau | --measure | --demo` → cognition **phono→ortho** (jointe §3). `python3 dictee/compress_probe.py` → compressibilité · `python3 dictee/test_decompose.py` → régression (asserts+seuils).
- `node evo/fitness_harness.js [seed] [n]` → bench fitness pendu · `node evo/phrase_engine_bench.js` → mode phrase moteur.
- App : ouvrir `app/omega-pendu.html` ; boutons « ✍️ Dictée diag » et « 🩹 Correcteur ».
