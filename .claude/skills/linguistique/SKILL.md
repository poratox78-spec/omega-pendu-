# Linguistique — playbook du correcteur dys

Périmètre : la grammaire (`dictee/correcteur_probe.py`, référence) + le speller (`dictee/speller_probe.py`), miroités dans `extension/dys-core.js` puis `app/omega-pendu.html` (et par ricochet le bake `correcteur.standalone.js` et le clone EN). Garde-fou cardinal : **FP=0 sur batterie** ; à l'échelle « FP=0 » vaut ~2 % sur français encyclopédique réel (requalification en tête de `dictee/CORRECTEUR.md`). Doctrine amont : `DOCTRINE.md` (§1 falsifiabilité, §3 jointe pas argmax, §4 une jonction à la fois, §5 réutiliser l'existant, §6 audit honnête). Les chiffres ci-dessous datent de 09/2026 — **ne jamais les recopier comme « courants » sans relancer la sonde** ; le message de commit du PR est le rapport qui fait foi.

## §1 — Le playbook « ajouter une règle »

**1. Mesurer les POPULATIONS d'abord, jamais coder sur un exemple.** Deux mesures obligatoires avant la première ligne :
- le **gold par alignement** : `data_local/dys_reel/gold_claude.jsonl` (72 productions dys réelles, ~6 800 mots, annoté par Claude — pas un expert). Exemple canonique (#616, a/à) : 95 « a→à » stricts alignés → la forme dominante est « a + nom NU » (41 cas), pas « a + la/le » (16) — le cadre à écrire n'était pas celui qu'on imaginait ;
- la **surface FP sur UD** (français correct) : compter les configurations où la règle TIRERAIT. Piège de sonde vécu : mesurer les tokens ÉCRITS « a », pas les « à » corrects. Sur 14 450 phrases, 36 avoir-corrects, quasi tous idiomes (« a lieu » ×13, « a besoin »…) ⇒ stoppables par liste fermée. Sans cette surface, on découvre les FP après câblage.

**2. Chercher le FAIT STRUCTUREL, pas un score.** Les règles qui tiennent reposent sur une impossibilité du français correct : « avoir sans déterminant n'existe qu'en idiomes » (#616) ; « [sujet nominal] + es/as/vas est impossible » (#615, coût UD zéro vérifié sur 14 450 phrases) ; « clitique élidé devant consonne = toujours faute » (élision, FP=0 structurel) ; « j'est n'est jamais valide ». Corollaire mesuré 3 fois (#598, #600, enquête ancres) : **le tagger est empoisonné par la faute elle-même** — un POS-tagger étiquette correctement un mot FAUX, et ~72 % des formes erronées dys ont un voisin erroné (Bodard 2020 = notre « ancre polluée »). Le fait structurel bat le tagger.

**3. Stop-listes FERMÉES, jamais le cas général.** La relaxation générale est falsifiée à chaque tentative (cf. §3). Ce qui marche : `{es, as, vas}` (lemme univoque) au lieu de « toutes lectures 1re/2e pers. » ; `_AVOIR_IDIOM`/`_A_NU_STOP` ; l'idiome « on faim/soif/peur/raison » fermé parce que le cas général « on + nom » a un FP construisible ; `IRREG_PART`, `DET_SKIP`, `VLIKE_STOP`, `NOUN_PL_STOP`, `_ELIDED_PRON` (et côté build, `CONJ_STOP` dans `build_cgram.py`). Une liste fermée coûte zéro poids et sa surface FP se mesure exhaustivement.

**4. Gardes d'ancre PAR RÈGLE — jamais de primitive lexicale globale (3 confirmations).** ① 92 % des FP ont une ancre parfaitement CONNUE du lexique (8 % de non-mots) ; ② « une **tré** faible exportation » : `tré` est un vrai mot, le test lexical ne voit rien — il faut du CONTEXTE ; ③ la garde « contradiction dét/nom » globale aurait cassé une règle juste 99 fois sur 100 sur les sondes (chiffre lui-même artefact du mélange, cf. §4 — mais la décision par-règle tient). Les 4 variantes éprouvées : ancre = mot inconnu → abstention (leur/leurs) ; déterminant contredit par le nom → abstention **sauf si `rule_noun_plural` sait réparer** ; ancre déjà corrigée par une autre règle → abstention (la cascade « à conservé » fabriquait « a conserver ») ; règle voisine qui sait réparer → confirmer.

**5. La rafale de mesure**, dans l'ordre, aucune n'est optionnelle :
- **batterie `CASES`** (`correcteur_probe.py --check`) : FP=0, code de sortie réel depuis #633 ;
- **échelle UD** : `dictee/fp_stress_test.py` (UD French ; les commits récents lisent 295/14 450 = 2,04 %, plafond CI 3 % ; garde CI rapide `fp_scale_probe.py` sur 2 500). ⚠️ Une part des « FP » UD sont de vraies fautes d'UD que la règle corrige — vérifier cas par cas avant de durcir ;
- **gold pipeline** : `dictee/dys_pipeline_probe.py` = **LE chiffre produit** (référence posée au #614 : 402 réparés / 19 cassés, ré-ancrée à chaque merge). Les mesures par couche mentent sur le produit (speller jugé seul se voit reprocher le travail de la grammaire). ⚠️ Le juge officiel **désaccentue** : les familles d'accent exigent le juge STRICT (les 106 fautes a/à du gold étaient invisibles du chiffre officiel) ;
- **précision par règle** : `dictee/dys_precision_probe.py` — deux références depuis #635, `dys_precision_ref.json` (moteur Python) et `dys_precision_nav_ref.json` (`--navigateur` = extension réelle dans Chrome via `extension/cdp_chrome.js`) : les deux modes divergent (SV 67,9 % réf vs 79,5 % produit), ne jamais les confondre ; audit fin à la demande `rules_audit_probe.py` (77 règles une par une, `--genere` branche `dys_gen.py`, `--ancres` mesure l'ancre) ;
- **4 parités** : `dictee/parity_corr.js` (app) · `extension/parity_core.js` (ext ⊆ Python + paliers) · `dictee/parity_pos.js` · `dictee/parity_os.js` ;
- **`dev.sh`** (~80 contrôles, code de sortie fait foi) : il attrape aussi les correctifs FAUX (garde genre v1 : rappel 210→168, stoppée par `gender_coll_probe`) — toujours le passer avant de conclure à un gain.

**6. Le miroir 3 MOTEURS.** Toute règle vit en trois exemplaires : Python référence → `dys-core.js` → app. La parité est obtenue par construction (mêmes assets : `build_cgram.py` → `inject_vdc.py` → `build_assets.py` → zip), pas par relecture. Pièges connus : `NOUN_POST` est une Map dans l'extension, un objet dans l'app (accesseur tolérant, #654) ; `omega-correcteur-dys.zip` et l'empreinte `sw.js` sont versionnés ET régénérés ⇒ en conflit de branche, prendre main puis RÉGÉNÉRER, jamais choisir un camp. Une garde de fréquence dans la grammaire est **non portable** (Python n'a que `cgram_words.json`, les JS ont `SP.FREQ`) — parité cassée ou asset nouveau.

**7. PR au verdict honnête, même falsifié.** Le modèle : **canal GROUPE #617** — classifieur de fermetures de groupe construit de bout en bout (entraîneur `build_bornes_clf.py`, asset byte-identique, 3 moteurs), +0,92 pt à la TÂCHE parseur-de-sujet… et au PRODUIT : **0 réparation / +1 FP** ⇒ consommation retirée, infrastructure gardée en hook OFF-inerte (pattern `_neoHeavyCDist`), tout futur consommateur devra faire SA preuve au produit. Un chantier falsifié se livre avec ses chiffres : c'est ce qui empêche de le refaire.

## §2 — La carte des primitives

- **Sujet** : `_subject_before` (pronom sujet effectif avant i) et `_np_subject`/`_npSubject` (parseur nominal [dét + nom-tête], enjambe « de X », **saute le cardinal** — bug #vingt-quatre-équipes —, se tait sur coordination « N et N ») ; `_ELIDED_PRON` (qu'/s'/n'/puisqu'… + pronom — propagé à 6 règles via `_prev_pron`/`_prevPron` au #613, avec la garde `_elid_kind` qui a éteint le FP verb_coord « et lorsqu'elle dort »→dorment) ; table de **prénoms** (#596, raccourci fiable par construction dans `rule_accord_sv_noun` #615) ; après une relative en « qui », le sujet est l'**antécédent** (#649). Instrument : `dictee/sujet_probe.py` (couverture 57,9 %, précision-quand-répond 95,2 % — le « mur » est fait d'abstentions FP-sûres voulues).
- **Bornes de proposition — trois canaux, JAMAIS fusionnés** (fusion mesurée : spécificité de la garde 89,7→36,8 %) : **`bb`** = ponctuation de l'AUTEUR, ~40 gardes FP=0 calibrées dessus — n'y rien mélanger ; **`pb`** = `_pred_bounds`/`_predBounds`, listes fermées (subordonnants, élidés « lorsqu'elle », relatifs ancrés, adverbes de liaison), consommé par la SEULE garde verbe-présence — parité avec les virgules de l'auteur pour zéro poids (rappel 42,3 vs 42,5 · spéc 78,9 vs 74,1) ; **`gb`** = `_group_bounds` (169 poids + biais, `bornes_clf.json`), **OFF-inerte, falsifié au produit** (#617).
- **Verbe-présence** : `_clause_no_finite_verb`/`_clauseNoFiniteVerb` — la garde qui taisait « les animaux mange » en texte non ponctué ; sert dans les deux sens (permettre de tirer à travers les subordonnées via `pb`, abstenir sinon) ; pilote historique = son/sont.
- **Posterior §3** : `_noun_gate` sur `NOUN_POST` (`cgram_noun_post.json` / `noun-post.txt.gz` / bloc `noun-post-gz`) — tire ssi P(NOM)≥0,5 ∧ P(VER)<0,01. Il existe pour rattraper le POS embarqué buggé (faute=VER, amis=ADJ alors que la fréquence dit 99 % NOM) ; sert genre, pluriel, a/à, a-NOM-NU, semi-auxiliaires.
- **Conjugaison** : `cgram_conj.json` (`build_cgram.py`) + sous-ensemble embarqué `cgram_hf.json`/bloc vdc-lex. L'histoire « sommes » (régression #83, réparée #613) : ignorer 8_Nombre en 1re/2e pers. était juste, mais le filtre LEFFF `forme[:2]==lemme[:2]` rejetait la seule supplétive (« so »≠« et ») → chaîne nous/vous morte pendant deux mois. Toute retouche de la table se **simule** avant régénération.
- **Paliers** : `tier_of` (réf.) ≡ `_tierOf` (app, dys-core) — rouge seulement dans le sous-cas MESURÉ sûr, orange sinon ; parité des paliers en CI.
- **Paliers du SPELLER** : auto / flag / **vigilance** — la référence n'émettait PAS le 3ᵉ avant le 05/09/2026 et **appliquait** ce que le produit propose au clic : toute mesure speller antérieure sur-compte les réparations (402/19 → 239/14 une fois la référence alignée, produit inchangé). Règle : avant de croire un gain speller mesuré en Python, vérifier que le juge VOIT le palier où le gain atterrit (#667). **Garde durable depuis le 05/09/2026 (soir)** : `palier_gold_probe.py` compare le PALIER rendu par le produit (`dys-core` + assets, `spellText`) et par la référence (`sp.correct_text`) sur chaque correction appariée du gold — accord ancré (92,4 % = 523/566 à la pose), rouge sur baisse OU désaccord nouveau, vue s'effondrer à 47,7 % avec l'ancien gate flag-only avant d'être crue. Locale (gold privé) : SAUTE explicitement sans corpus. **Première prise (06/09, contexte-first porté)** : un contexte qui ne pèse que dans le TRI (POS attendu, DET_G) cache ses asymétries jusqu'à ce qu'il décide un PALIER — `DET_G` Python avait « du »/« au » en trop depuis #665, invisible, vu rouge au premier port qui s'en sert pour affirmer. Règle : quand une brique de contexte passe du tri au palier, re-vérifier sa TABLE contre le produit, pas seulement sa logique. **07/09 (tokeniseur porté)** : `speller_probe.correct_text` tokenise désormais COMME le produit (`TOK_JS`, apostrophe dans le token) et passe par `spell_token` (l'étage d'élision) — toute sonde qui appelle `correct_token` directement sur ses propres tokens sans apostrophe ne mesure PAS le produit. L'« angle mort » de parity_speller (« Python corrige / produit muet ») était pour 27 corrections sur 35 un artefact de tokenisation. **Depuis le 07/09 (suite)**, `palier_gold_probe` compare aussi le palier « mot inconnu » (4ᵉ palier `inconnu`, 276 paires de plus) et ANCRE ce qu'un seul moteur rend (2 au 07/09) : l'angle mort est énuméré, plus estimé. Ce que ça a montré tout de suite : 6 non-mots que la référence propose en orthographe|vigilance là où le produit ne les trouve qu'en « mot inconnu » — la génération des candidats diverge en amont du tri. **b_slip, verdict final (07/09)** : re-mesuré sur cette surface, la référence reproduit les casses du port JS de #664 (trés, aprés, gran perdu) — l'« asymétrie de moteur » cherchée pendant 4 PR n'existait pas, c'était la référence incomplète. Règle : avant de chercher une asymétrie entre moteurs, vérifier que la référence a TOUTES les étapes du produit sur le chemin de la décision ; et ne jamais créditer un +2 pipeline sans regarder la garde de palier ET la colonne « APPLIQUÉ FAUX » de `dys_pipeline_probe` (posée le 07/09 nuit : avant, une correction appliquée fausse tombait en MUET). Méthode qui a payé deux fois : pour trouver POURQUOI le produit rend null, **instrumenter une COPIE de dys-core** (chaque `return null` tracé par ligne) plutôt que raisonner sur la source — c'est ainsi que l'hypothèse « génération des candidats » est tombée en 10 minutes (pools identiques ; la cause était la ré-sélection OMISSION/_DPAIR de w1). **08/09 : OMISSION + _DPAIR portés** (`subseq`, `lev_b`, `_DPAIR` décalqués ; 17/18 témoins ≡ produit, accord 98,9 %). Le 18ᵉ a nommé la brique suivante : la TABLE DE GENRE — le produit charge `gender-acc.json.gz` (59 916 formes Morphalou, un asset committé), la référence lit ADJ/GEN de Lexique4 ; même mot, genre connu d'un seul côté (agressée), et le tri diverge. **09/09 : briques de contexte alignées** — fenêtre du nombre (3 → 4), invariables dans le tri (`nmatch` ≡ `nm`/`nmP`/`sInvarS`), tables de genre du produit (`vdc-lex.json` g/gn/a + `gender-relaxed.tsv.gz`, chargées depuis `extension/assets/`) ; accord 99,2 %, même mot 294/294 en vigilance. Leçon : une brique portée « pour une étape » (nm_p pour contexte-first, #672) doit l'être PARTOUT où le produit l'emploie — le tri l'utilisait aussi, et l'écart n'est devenu visible qu'en élargissant la fenêtre (2 rouges, frence/desue). **10/09 — série CLOSE (#679)** : les six dernières étapes portées (_AFIX, e muet du futur avec les tables vdc.cj, soudure à/a+verbe, élongation, _slipMot auto, _aux participe), accord de palier **100 % (880/880)**. Règle qui tient depuis dix maillons : la référence ne mesure le produit que si elle a TOUTES ses étapes sur le chemin de la décision, dans le MÊME ordre, avec les MÊMES tables (assets committés, pas des tables maison) — et une garde qui compare le palier mot à mot est ce qui l'a rendu vérifiable. Désormais un désaccord de la garde est un défaut de PORT, pas un mystère de moteur ; un gain mesuré en Python est un gain du produit ; et une casse vue par la référence est une casse du produit (revérrons→revérerons, 15ᵉ cassé, invisible avant). Autre leçon du jour : le FP AUTO de §1 ne faisait que s'imprimer — sortie dure posée. **Instrument (10/09 suite)** : `atStart` ≡ premier token du texte (le produit ne corrige jamais une majuscule ailleurs) ; la garde de palier dumpe TOUTES les familles du produit — un « produit muet » peut être un « produit : autre famille » (« la 1ere » → nombre) ; et 37/68 appliqués faux sont « bon lemme, mauvaise flexion » : avant de chercher une faute d'orthographe dans les rouges appliqués, regarder si c'est la FORME. **11/09, premier chantier de moteur après la série** : le « e » muet du futur — RECENSER d'abord (8 justes / 2 faux / 0 UD), trouver le trait qui sépare (fréquence du verbe reconstruit ≥ 1/M), poser la garde dans les 3 moteurs via `omega_edit`, mesurer avec le juge aligné (accord 100 % inchangé, −1 cassé, −1 appliqué faux). Une règle de moteur se justifie par son recensement, pas par son exemple fondateur. Census des oranges : `vig_census_probe.py` (le rouge portait sur le NET, #625 ; tourne aussi en worktree depuis #655, il se sautait en silence avant).
- **Textes d'explication** (11/09/2026, audit dans le vrai Chrome) : deux routes — `REMED` (remède par FAMILLE, via `flagsToFacts`/`_corrFam`) et `ctxHint`/`_ctxHint` (💡 par CORRECTION : `_HPROBE` substitution fenêtrée, `_accHint` gouverneur, `_erHint` mordre/mordu) — aucun test ne les lisait, et elles se contredisaient sur la même faute (« mordre » servi sur « clé → clés », « ma » qui commande « heures » à six mots). Règles : un test de substitution ne vaut que si la finale CHANGE DE NATURE (`_ervk`) ; le gouverneur d'un nom est le cardinal d'à côté avant tout déterminant lointain ; un indice contradictoire vaut moins que rien (silence) ; une famille se décide sur le NOM de la règle avant l'heuristique de forme (`terminaison -er` = accord ; w === sg n'est pas un accent). Sonde : `dictee/textes_probe.js` (rouge 26 → vert), qui compare aussi `REMED`/`_HSUB`/`_HPROBE` app ≡ ext — éditer les deux fichiers par `omega_edit`, à l'identique.
- **Formes nues qui polluent le lexique** (11/09/2026, `_AFIX_MIN`) : `mere`, `age`, `ame`, `reparer`… sont des ENTRÉES de Lexique4 (sous-titres, ≤ 10/M) à côté de la sœur accentuée (≥ 50×) — le speller se tait sur un mot « connu », et la règle de genre lit le mauvais genre. Recenser AVANT de poser : Lexique4 (nue rare, sœur fréquente) × UD correct (0 en minuscules ; les majuscules « Ame V », « Special » existent → `tok === low`) × corpus dys (gold = sœur accentuée) ; exclure les mots valides (cote, prive, voila…) et les graphies de 1990 (maitre, ile, gout). **Biais du juge découvert au passage : `DP.eq` désaccentue — les fautes d'accent seul (273/6 217 mots) et les accents cassés (4 a → à) lui sont invisibles ; ne pas mesurer un chantier d'accents avec lui sans la colonne stricte.** Colonne posée le 12/09 (bloc ACCENTS de `dys_pipeline_probe`) : 273 / 165 réparées / 4 cassés — et lire les cassés un par un : 1 des 4 était une erreur du GOLD, 1 un cas ambigu sans le sens (« se manifestent a un cocar » = « ce manifestant a un cocard »), 2 de vraies casses tracées jusqu'à `vlike`. Réparées le 12/09 (suite) par deux gardes de DONNÉES de `vlike` : `lui` dans VLIKE_STOP/VSTOP (homographe verbal rare, luire), et du/au/aux ajoutés à la garde déterminant (NUM_DET ne contient pas les contractions — DET_G non plus, à dessein, pour le genre). Leçon : quand une règle de contexte casse, regarder d'abord les PRIMITIVES qu'elle appelle (`vlike`, `is_verb`, les listes) avant la règle.
- **Angle mort n° 2 du juge (12/09/2026)** : `pyramide` n'appliquait que les suggestions `isalpha()` — l'apostrophe passait à la trappe avec l'espace, donc toute la couche ÉLISION du produit (Jai → J'ai) était invisible : 286 → 294 réparés et 67 → 73 appliqués faux rien qu'en l'admettant (`_mot`). Règle : avant de mesurer une famille, vérifier que le juge peut ÉCRIRE sa réponse (accents, apostrophe, casse) — sinon il mesure le silence. Formes figées soudées : `_APOS_FIX` (liste close, recensée : speller ∅, UD 0, corpus dys 2).
- **Accord de l'adjectif antéposé** (13/09/2026, `rule_adj_ante_plural` / `rAdjAntePl`) : après un déterminant pluriel non ambigu (`PLURAL_DET`), un adjectif de la classe fermée `_ADJ_ANTE` est toujours au pluriel — l'ancre d'« accord pluriel nom » sans le doute du nom. Table de pluriel CLOSE (pas de morphologie : beau→beaux, nouveau→nouveaux, gros/vieux/mauvais invariables → exclus), premier/dernier exclus (UD : « ses premier et sixième »), garde trait d'union AVANT ET APRÈS (`_SEG.hy[i]||hy[i+1]` — `hy[k]` = trait dans l'espace qui PRÉCÈDE k, « mes grand-parents » l'a appris). Méthode qui a payé : partir du RECENSEMENT des muets par famille × contexte (census5*.py), pas des 12 phrases de l'audit. Suite ⑤-b : la règle du NOM lit le déterminant à i-2 à travers un adjectif de `_ADJ_ANTE` (mêmes gardes) — une règle d'adjacence se tait dès qu'un mot s'intercale ; vérifier la traversée AVANT de croire à un silence de garde.
- **Féminin manquant** (13/09/2026, 55 muets recensés) : trois paquets, une seule ancre. (A) le participe après « je me suis » suit le genre de l'AUTEUR — inconnaissable dans le texte, donc JAMAIS de règle (la moitié des « je » sont masculins). (B) « la cheminé / la vu / une parti » : déterminant féminin non ambigu + liste close de noms en -ée dont la forme sans e est un participe masculin (`rule_fem_ee` / `rFemEe`, UD 0). (E) adjectif après nom féminin : l'ancre attrape les homographes (« la voiture SUR », « la mer SAUF », « sa voiture CHER ») — 2 cibles pour 3 pièges dans le gold, différé. Règle générale : quand le gold porte une information ABSENTE du texte (genre de l'auteur, sens), le silence est la bonne réponse.
- **Accent : présent ou participe ?** (14/09/2026) Quand un mot nu a deux accentuations (« decide » → décide / décidé), le tri par fréquence choisit le participe (95/M contre 25/M) ; le speller a une étape « participe après auxiliaire » mais n'avait pas sa symétrique. Posée : « présent après pronom sujet » (clitiques traversés, stop sur auxiliaire/copule), AVANT la bascule de genre — laquelle lit le contexte à travers le pronom (« la voiture il decide » → décidée). Recensé 6/6 au présent. Leçon : à chaque étape de contexte du speller, chercher sa symétrique (aux ↔ pronom, det ↔ verbe) et vérifier l'ORDRE des étapes — la première qui retourne gagne.
- **Orange OS** : `os_subject_probe.py` (4 routes), LM `os_subj_lm.json.gz` (`lsc()`, parité `parity_os.js`) — 13 954 unigrammes : trop petit pour servir de dominance en contexte (4 ordres de grandeur sous LanguageTool), garder pour l'orange seulement.

## §3 — Les falsifiés, avec leurs chiffres (ne pas refaire)

- **Relaxation p3 générale** (toutes lectures 1re/2e pers. dans l'accord SV) : +11 flags UD dont ~9 FP réels (« remplies »→remplient, « CHANTONS sous la pluie »→chante), rappel unique NUL (#615). La liste fermée {es,as,vas} fait le travail à coût zéro.
- **`gb` câblé au parseur de sujet** : 0 réparation gold / +1 FP UD malgré +0,92 pt à la tâche (#617) — les gardes des règles neutralisent le gain, il ne reste que le mode de défaillance.
- **« Lettre inventée »** pour départager les lemmes du speller : −11 bonnes corrections pour −3 mauvaises évitées à l'échelle (joli sur 3 exemples choisis).
- **Relâcher `dk>0`** (accord SV sujet-nom en milieu de phrase, via posterior) : +18 FP pour 2 patterns récupérés — `dk==0` est une garde structurelle (homographes prép/verbe, sujet distant), pas un manque de lexique.
- **Lexique/posterior plus riche pour son/sont** : goulot = contexte/structure, pas couverture (les 8 ratés = sujet pluriel distant ou artefacts). Ne pas construire.
- **Le tagger comme garde dure** : « exiger tag NOUN » → rappel genre 210→168 (il punit les noms mal tagués, exactement ce que le posterior rattrape). Garde retenue : abstention seulement si tag ADJ ET un NOUN suit dans les 2 jetons — rappel identique, coût nul.
- **Restauration de virgule comme cible du classifieur de bornes** : F1 34 contre 64 pour l'or STRUCTUREL des arbres UD (clauses 2 bords + adjoncts + appositions).
- **Fusion des canaux de bornes** dans la garde verbe-présence : spécificité 89,7→36,8 %.
- **Désambiguïsation mot-court par fréquence** (speller) : +19 FP UD (von→vont) ou abstention = l'actuel. **Relaxation `nbhomog≤1`** du pluriel : FP 22→47 ET « des ami » toujours raté. **Élargir -é/-er via le POS 155k** : FP 53→98 (74 borné à avoir) — le contexte, pas l'appartenance lexicale.

## §4 — Les juges et leurs biais

- **Juge tolérant vs strict.** `dys_precision_probe.eq` normalise les accents : mots fautifs 13,1 % (tolérant) contre 17,1 % (strict) sur les 6 dictées. Tolérance justifiée pour JUGER une correction, pas pour DÉCRIRE un corpus — et elle rendait invisibles les 106 fautes a/à du gold. Familles d'accent ⇒ juge strict, toujours.
- **Composition du corpus** (`corpus_profile_probe.py`, à lire avant tout « % dys ») : le « corpus dys réel » est 92,7 % de SONDES à faute unique, 7 % de généré, 0,3 % de vraies dictées. Les deltas avant/après restent valides ; **les ABSOLUS mesurés sur les sondes ne se généralisent JAMAIS au dys réel** (les 3 griefs contre `dys_gen.py` — densité ×2, « ×29 sur les déterminants », mots-outils — venaient tous de la comparaison au mélange ; tous rétractés). Et la « convergence » avec Bodard 2020 n'en est pas une : FFDys + ASEI SONT les corpus de Bodard.
- **« L'instrument avant le moteur »** — à chaque fois que le moteur semblait faible, c'est la mesure qui était fausse, et réparer l'instrument a trouvé de vrais défauts dans la foulée : ① corpus dominé par les sondes ; ② virgule jugée contre UD (toute virgule facultative = FP) ; ③ speller jugé isolément (on lui reproche le travail de la grammaire) ; ④ la sonde pipeline tokenisait sans apostrophes typographiques et abandonnait 32 % des corrections ; ⑤ la référence Python n'était pas déterministe (`edits1` en `set()` + `_cmp` pairwise : 10/598 corrections dépendaient du hachage) ; ⑥ `dys_pipeline_probe` reconstruisait le texte par `' '.join(Tc)` et **jetait la ponctuation de l'auteur** — la sonde mentait de 4 réparations (#614) ; ⑦ la table de précision mesurait le harnais, pas le produit (#635, d'où les deux fichiers de référence) ; ⑧ `dev.sh` avalait les sorties des contrôles (#620) ; ⑨ le census se sautait en silence dans les worktrees (#655). Symétrique : l'instrument attrape aussi vos correctifs faux — dev.sh d'abord.
- **Bruit et déterminisme.** Avant #566 le chiffre pipeline variait de ±5 selon l'exécution : ne jamais comparer deux variantes sur un écart de cet ordre, et vérifier qu'une différence se réplique (graines neuves, placebo).
- **Le générateur** (`dys_gen.py`) mesure bien les FP (corrigé certain par construction), **mal le rappel des règles rares**, et produit des artefacts (2 signalements sur 5 en étaient) : vérifier chaque cas avant de durcir. Même consigne pour UD : beaucoup de « FP » y sont de vraies fautes du corpus.
